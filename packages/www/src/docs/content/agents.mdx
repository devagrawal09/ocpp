---
title: "Agents"
---

Agents combine a system prompt, model preference, and display metadata into a
reusable assistant profile. An agent grants no tools: a session's tools come
from its [tool list](/tools). OC++ includes agents for common workflows, and
you can override them or add your own in configuration or Markdown files.

## Built-in agents

| Agent                   | Mode       | Purpose                                                                                                         |
| ----------------------- | ---------- | --------------------------------------------------------------------------------------------------------------- |
| **Build** (`build`)     | `primary`  | Default coding agent. Without an `init.ts` it has every tool.                                                   |
| **Plan** (`plan`)       | `primary`  | Planning agent. Without an `init.ts` it reads, searches, and asks, but cannot edit files or run shell commands. |
| **General** (`general`) | `subagent` | General-purpose research and multi-step work with the tools its caller passes.                                  |
| **Explore** (`explore`) | `subagent` | Code and web exploration. Callers typically pass it `read`, `glob`, `grep`, and `webfetch`.                     |

OC++ also has hidden `compaction`, `title`, and `summary` system agents.
They run internal maintenance tasks and are not available for direct use. There is no built-in
`scout` agent in V2.

You can override a built-in agent with an entry of the same ID. Set
`disabled: true` to remove one.

## Default agent

Set the primary agent used when a session has not selected one:

```jsonc title="ocpp.jsonc"
{
  "$schema": "https://ocpp.ai/config.json",
  "default_agent": "reviewer",
}
```

The configured agent must exist, must not have `mode: "subagent"`, and must not
be hidden. If it is unavailable, OC++ falls back to `build`, then to the
first visible agent that can run as a primary agent. This selection does not
rewrite the agent already stored on an existing session.

## Modes

An agent's `mode` controls where it can run:

| Mode       | Behavior                                                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `primary`  | Can be selected as the main agent for a session. It cannot be launched as a subagent. This is the default for a custom agent when `mode` is omitted. |
| `subagent` | Can run in a child session through the `subagent` tool, but cannot be selected as the main agent.                                                    |
| `all`      | Can be used either way.                                                                                                                              |

Subagents run in child sessions with fresh context. A primary agent can invoke
one with the `subagent` tool, either in the foreground or in the background.

A child has exactly the tools its parent passes in the `subagent` call's
`tools`, drawn from the parent's own tools. Without `tools` it has none. See
[Tools](/tools#subagents).

A child session runs in its parent's directory unless the `subagent` call
passes `root`, an existing absolute directory such as a separate git worktree.
The child then runs under that directory's own configuration, not the
parent's: its agents, models, MCP servers, plugins, and instructions. The agent
must be defined there, its model there decides the child's driver, and the
tools the parent passes must exist there by the same paths. The child keeps its
directory when continued. See [Session drivers](/drivers) for running subagents
with Claude Code, Codex, or Pi.

## Configure agents

### Markdown files

The recommended file locations are:

```text
~/.config/ocpp/agents/<name>.md
.ocpp/agents/<name>.md
```

OC++ discovers project `.ocpp` directories from the current directory
up to the project root. The path below `agents/` becomes the agent ID, so
`.ocpp/agents/team/reviewer.md` defines `team/reviewer`.

Frontmatter uses the same fields as an entry under `agents`. The Markdown body
becomes `system`:

```md title=".ocpp/agents/reviewer.md"
---
description: Reviews changes without modifying files
mode: subagent
model: anthropic/claude-sonnet-4-5#high
color: "#ff6b6b"
steps: 8
---

Review for correctness, security, regressions, and missing tests.
List findings in severity order with file and line references.
```

### JSON or JSONC

Use the `agents` field in any [OC++ configuration file](/config):

```jsonc title="ocpp.jsonc"
{
  "$schema": "https://ocpp.ai/config.json",
  "default_agent": "reviewer",
  "agents": {
    "reviewer": {
      "description": "Reviews changes for correctness, security, and missing tests",
      "mode": "all",
      "model": "anthropic/claude-sonnet-4-5#high",
      "system": "Review the current changes. Report findings before any summary.",
      "color": "#ff6b6b",
      "steps": 8,
    },
  },
}
```

Agent definitions merge in configuration order. Later scalar fields replace
earlier values, and request maps merge by key.

## Options

### `description`

Explains the agent's purpose. It is optional, but strongly recommended for
subagents because OC++ includes it in the subagent catalog shown to the
model.

### `mode`

Accepts `primary`, `subagent`, or `all`. The default is `all`.

### `model`

Selects a model using `provider/model` with an optional `#variant`:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": "anthropic/claude-sonnet-4-5#high",
    },
  },
}
```

The equivalent expanded form is:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-4-5",
        "variant": "high",
      },
    },
  },
}
```

This is the preferred model when the agent is activated. The session's selected
model is stored separately; creating or switching a primary session with only
an agent ID does not itself change that session model.

A new child session takes its driver from its agent's configured model: a
`claude/`, `codex/`, or `pi/` model runs the child with that
[session driver](/drivers), and any other provider runs it with the OC++ runner.
An agent with no configured model gets the parent session's driver, and on the
OC++ runner it inherits the parent's model. A `subagent` call can name another
`driver` or `model`, and a continued child keeps its own driver.

```jsonc
{
  "agents": {
    "reviewer": {
      // Runs as Claude Code with high effort.
      "model": "claude/opus#high",
    },
  },
}
```

### `system`

Sets the agent's system prompt. A non-empty value replaces OC++'s
provider-specific base prompt for that agent. Project instructions, skills,
references, and other instruction sources are still added separately.

For a Markdown agent, use the document body instead of a `system` frontmatter
field.

### `steps`

Sets a positive maximum number of model steps. On the final allowed step,
OC++ removes tools and asks the model to summarize its work in text. New
user input resets the allowance.

### `hidden`

When `true`, removes the agent from normal agent listings, interactive
discovery, and the subagent catalog advertised to models. It is a visibility
setting, not a security boundary.

### `color`

Sets the agent's UI color. Use a six-digit hex color such as `#ff6b6b`.

### `disabled`

When `true`, removes the agent definition at that point in configuration
loading. This works for built-in and custom agents.

### `request`

The V2 schema accepts per-agent request `headers` and JSON `body` overlays:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  The current V2 session runner preserves these overlays on the agent definition but does not yet apply them to model
  requests. Configure effective request settings on the provider, model, or model variant instead. Do not use legacy
  top-level agent fields such as `temperature`, `top_p`, `prompt`, `disable`, or `maxSteps` in new V2 configuration.
  OC++ ignores an agent's `permission`, `permissions`, and `tools`; use [tool lists](/tools) instead.
</Callout>
